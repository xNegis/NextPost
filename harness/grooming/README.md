# Grooming Notes

Create one working file per consumed ticket as `RF-XX-grooming.md`.

Use this template:

```markdown
# RF-XX - Ticket title - Grooming

## Status

`Grooming - questions open`

## Trello snapshot

- Title:
- URL:
- List:
- Labels:
- Captured on:
- Last Trello activity at intake:

### Description and acceptance criteria at intake

Copy the readable ticket content here.

## Intended outcome

What we currently understand the ticket is trying to achieve.

## Current code findings

What exists today and which concrete areas appear affected.

## Dependencies and conflicts

Related tickets, plans, decisions, and ordering constraints.

## Candidate approach

Options, trade-offs, and current recommendation. Keep unaccepted recommendations labelled as such.

## Questions

### Open

- Material question, context, options, and recommendation.

### Resolved

- Confirmed decision and date.

## Proposed scope

### In scope

- Proposed item.

### Out of scope

- Proposed boundary.

## Validation outline

How the eventual implementation could be proven correct.

## Readiness checklist

- [ ] Desired outcome is unambiguous.
- [ ] Scope and exclusions are confirmed.
- [ ] Code impact was inspected.
- [ ] Dependencies and conflicts are resolved.
- [ ] Technical approach is selected.
- [ ] UX and failure states are confirmed where applicable.
- [ ] Security, privacy, retention, and abuse implications are resolved where applicable.
- [ ] Data migration and operational implications are resolved where applicable.
- [ ] Test and manual validation expectations are agreed.
- [ ] No material question remains.
- [ ] Product owner explicitly approved plan finalisation.
```

Grooming notes are not implementation authority. Preserve proposals as proposals until the product
owner confirms them.
